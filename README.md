# qmk-userspace

My [QMK External Userspace](https://docs.qmk.fm/newbs_external_userspace): the
code my keyboards share and the setup to build them all. Each keyboard's keymap
lives in its own repository (listed below); QMK Firmware itself stays a vanilla
clone.

```
qmk.json      build targets for `qmk userspace-compile`
keymaps.txt   which keymap repository is cloned into which keymap folder
users/nedsi/  shared code: layers, row macros, custom keycodes, tap dances
keyboards/    keymap clones, one repository per keyboard (git-ignored)
```

Each keyboard keymap is its own repository, cloned into its QMK keymap folder.
This repository ignores those folders (`keyboards/**/keymaps/nedsi/`), so it
never pins a keymap commit: a build uses whatever each clone has checked out.

target to `qmk.json`.

## Shared code (`users/nedsi`)

Built into every keymap named `nedsi`, except the standalone BDN9, Planck,
Tractyloder and Zima keymaps, whose `rules.mk` opts out with
`USER_NAME := nedsi_none`.

| File | What it holds |
|---|---|
| `nedsi.h` | The layer list (Main, Gaming, Sym, Acc, Num, Nav, Misc), the home-row mod-taps `HOME_A` to `HOME_SCLN` (Gui, Alt, Ctrl, Shift, and Acc on G and H), `UNDO` and `REDO`. |
| `wrapper.h` | Row macros: the three main rows of each half, for every layer (drawn below). |
| `tapdance.c` | Tap dances: `CACCCV` (copy, paste, select all), `UNIWL` (Unicode input mode), `NXTPRV` (next or previous track). Per-key tapping terms for the home-row mods. |
| `custom_strings.c` | Keycodes that type accented letters (é è ê ë à â ä î ï ô ö ù û ü ç), `€`, `°`, `·`, the shrug and an email sign-off. |
| `custom_unicode.c` | The Unicode map for the circumflex and diaeresis dead keys. |
| `custom_shift_keys.c` | Shifted overrides: `:` gives `;`, `<` gives `>`, Backspace gives Delete, `&` gives `\|`. |
| `combos.c` | Combos (J+K Backspace, F+D Escape, ...), currently off: `COMBO_ENABLE = no` in `rules.mk`. |
| `config.h` | 170 ms tapping term (adjusted per key), permissive hold, no quick-tap repeat, Unicode modes Linux, macOS and WinCompose. |
| `rules.mk` | Features: tap dance, Unicode map, Caps Word, NKRO. |

Keymaps place these rows inside their own layout, adding outer columns, thumbs
and layer keys. Skeletyl, Microdox and Atreus 44 use the Main home row as is,
with its mod-taps; Scylla, Kyria and Keyboardio Atreus write their own home row
without mods.

- `X/Mod` and `X/Lay` keys type X when tapped, and act as the modifier or layer while held.
- `Unicode`: tap Linux input, hold WinCompose input, double-tap macOS input.
- `&` sends `|` when shifted.
- `Shrug` types `¯\_(ツ)_/¯`.
- The dead keys add a circumflex or diaeresis to the next letter.
- `Boot` reboots into the bootloader, for flashing.

## Setup

1. Install the QMK CLI and toolchains. The official route is
   `curl -fsSL https://install.qmk.fm | sh`. Equivalent manual steps:
   `uv tool install --with pip qmk`, then extract the latest
   [qmk_toolchains](https://github.com/qmk/qmk_toolchains/releases) and
   [qmk_flashutils](https://github.com/qmk/qmk_flashutils/releases) releases
   into `~/Library/Application Support/qmk` (flashutils under `bin/`).
2. Clone QMK Firmware and point the CLI at it:

   ```sh
   git clone --recurse-submodules https://github.com/qmk/qmk_firmware.git ~/repos/qmk_firmware
   qmk config user.qmk_home="$HOME/repos/qmk_firmware"
   ```

3. Clone this repository, register it as the overlay, then clone every keymap
   listed in `keymaps.txt`:

   ```sh
   git clone git@github.com:ned-si/qmk-userspace.git ~/repos/qmk-userspace
   qmk config user.overlay_dir="$HOME/repos/qmk-userspace"
   cd ~/repos/qmk-userspace
   grep -v '^#' keymaps.txt | while read -r dir repo; do git clone "git@github.com:$repo.git" "$dir"; done
   ```

4. `qmk doctor` should end with "QMK is ready to go".

## Build

```sh
qmk userspace-compile                               # every target in qmk.json; firmware lands here
qmk compile -kb bastardkb/scylla/promicro -km nedsi # one keyboard
```

## Flash

```sh
qmk flash -kb <target> -km nedsi
```

Then put the keyboard (or one half) in bootloader mode; the CLI waits for it
and flashes. Split keyboards take the same firmware on both halves, flashed one
at a time. Each keymap README says how to enter its bootloader.

## Layer diagrams

Each keymap README has its layers drawn as text, between `<!-- layers:start -->`
and `<!-- layers:end -->`, and so does this README for the shared layers. CI
redraws them on every push (to a keymap repository for its README, to `main`
here for this one) and commits the README back as `github-actions[bot]` when
they changed, so `git pull` after pushing. To redraw locally instead, from this
directory (needs a C compiler and the QMK CLI):

```sh
python3 util/layers.py keyboards/bastardkb/scylla/keymaps/nedsi
python3 util/layers.py users/nedsi   # the shared layers in this README
```

It expands only this userspace's macros, takes key positions from QMK's layout
data (or from a layout macro defined in the keymap), reads tap dance and combo
behaviour from the keymap's own code, and draws the layers in the order Main,
Num, Sym, Acc, Nav, Misc, then Gaming.

## CI

`.github/workflows/build.yml` builds the firmware on GitHub Actions, following
QMK's own userspace workflow plus a step that clones the repositories in
`keymaps.txt`:

- Here: every push and pull request builds every target, since the shared
  code in `users/nedsi` affects them all. Pushes to `main` publish all the
  firmware as a release.
- In each keymap repository, `.github/workflows/build.yml` calls this workflow
  to build just that keyboard from the pushed commit, and publishes it as a
  release of that repository.
- Releases are tagged with the short commit SHA they were built from, so tags
  never move, and only the last 5 are kept (older releases and their tags are
  deleted). The newest one is always at `/releases/latest`, for example
  [qmk-userspace's](https://github.com/ned-si/qmk-userspace/releases/latest)
  with every keyboard.
- A branch pushed here builds the keymap branches of the same name, where they
  exist, so a change spanning repositories can be tested before it reaches
  `main`. A manual run can name the keymap branch instead.

To flash from any machine: download the file from the latest release, then
`qmk flash <file>` or the usual bootloader drag-and-drop.

## Updating

```sh
git -C ~/repos/qmk_firmware pull --recurse-submodules
cd ~/repos/qmk-userspace && git pull
grep -v '^#' keymaps.txt | while read -r dir repo; do git -C "$dir" pull; done
```

Keymap changes are committed and pushed from inside the keymap clone, to its own
repository. Shared code in `users/nedsi` is committed here.
